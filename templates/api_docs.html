Dodman Group · Data Cleaning Proxy

API Integration Guide

A stateless, in-memory CSV and XLSX cleaning service. Send a file and a JSON config describing what to do with each column — receive cleaned rows as JSON or CSV, either streamed directly back in the response or delivered to your webhook endpoint asynchronously.

⚑

All requests require an API key sent as a Bearer token in the Authorization header. Obtain your key from the dashboard.

Base URL

endpoint
https://your-deployment-url.com/api/v1

Authentication

Pass your API key as a Bearer token on every request.

http header
Authorization: Bearer dk_test_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
✕

Never send your API key in a URL query string, request body, or client-side JavaScript. Treat it like a password.

Environments

Every key is scoped to exactly one environment. The environment is encoded in the key prefix and enforced server-side on every request.

PrefixEnvironmentBehaviour
dk_test_Test Files silently truncated to the first 20 rows. 1 MB file cap. No billing. Safe for development and CI pipelines.
dk_live_Live Full file processing. File cap and row quota enforced by tier. Every request is logged to the billing ledger. Rejected unless the server runs in DODMAN_ENV=production.
dk_sandbox_test_99Open Sandbox Public key for the interactive sandbox UI. Limited to 5 requests per day per IP. 20-row cap. Free.
⚠

Using a dk_live_ key against a development server returns a 400 INVALID_ENVIRONMENT_KEY error. This prevents accidental production data from being sent to non-production infrastructure.

Rate Limits & Monthly Quotas

Requests are rate-limited per API key. Separately, each key has a monthly row quota. Both are enforced independently.

Request Rate Limits

TierRate LimitBurst CapScope
free60 requests / hour5 / minutePer API key
starter500 requests / hour50 / minutePer API key
pro99,999 requests / hour500 / minutePer API key
sandbox5 requests / day—Per client IP

Rate-limited requests return 429 Too Many Requests with a Retry-After: 60 header.

Monthly Row Quotas

TierRows / MonthNotes
free / sandbox10,000Shared across test and sandbox keys.
starter500,000Counted against live keys only.
pro5,000,000Counted against live keys only.

When you are near your quota and the uploaded file would push you over, the file is trimmed to the remaining rows rather than rejected outright. The response includes an X-Quota-Rows-Remaining header so you can track consumption programmatically.

File Size Limits

File size is enforced at the gateway before any parsing begins, returning a clean 413 immediately on oversized uploads.

TierMax File Size
test / sandbox keys1 MB
starter50 MB
pro500 MB
✦

Pro chunk-streaming: Pro-tier files over 10,000 rows are processed in 10,000-row volatile batches, keeping server RAM flat regardless of file size. A 500 MB file uses no more memory than a 10 MB file.

POST /clean

POST/api/v1/clean

Upload a .csv or .xlsx file for in-memory cleaning. Returns cleaned data directly (stream download) or, if X-Webhook-URL is provided, queues delivery and returns 202 Accepted immediately.

Form Fields

FieldTypeDescription
file *File The .csv or .xlsx file to clean. Encoding is auto-detected (UTF-8, UTF-16, Latin-1, Shift-JIS, Windows-1252, and more).
configJSON string Cleaning configuration object. See Config Schema. Optional — omit to strip whitespace from all columns.
output_format"json" | "csv" Response format when no webhook URL is supplied. Defaults to "json".
dry_runbool When true, validates the config against the file's column headers and returns immediately — no rows are cleaned, no credits consumed. See Dry-Run Mode.
dedupe_allbool When true, removes rows where every column is identical (whole-row deduplication). Starter tier: max 10,000 rows. Pro: unlimited. See Deduplication.

Request Headers

HeaderRequiredDescription
AuthorizationYesBearer dk_test_… or Bearer dk_live_…
X-Webhook-URLNo When present, cleaned JSON is POSTed to this URL asynchronously and the endpoint returns 202 with a job_id you can poll. Starter+
X-Clean-ConfigNoCleaning config as a JSON string. Overrides the config form field.
X-Output-FormatNoHeader alternative to the output_format form field.
X-Dry-RunNoSet to true to activate dry-run mode. Header alternative to the dry_run form field.
X-Dedupe-AllNoSet to true to activate whole-row deduplication. Header alternative to dedupe_all.
X-Crypto-SaltNo Salt string used when applying the ENCRYPT rule. Combined with each cell value before hashing. Kept entirely in volatile memory — never logged or stored. Pro only

GET /jobs/{job_id}

GET/api/v1/jobs/{job_id}

Poll the status of an async cleaning job created by a webhook-mode POST /clean. The job_id is returned in the 202 response body. Requires the same API key that created the job.

⚑

Jobs are only created when X-Webhook-URL is supplied. Direct download requests do not create job records. Starter+

Status Lifecycle

StatusMeaning
queuedJob created. Webhook dispatch has not yet started.
processingFirst delivery attempt is in progress.
deliveredWebhook accepted the payload with a 2xx response. Terminal state.
failedAll retry attempts exhausted. See the error field for details. Terminal state.

Webhook Retry Schedule

On a non-2xx response or timeout, delivery is retried automatically. 4xx errors from your server short-circuit the retry loop immediately (retrying a bad config won't help).

AttemptDelay
1st (initial)Immediate
2nd30 seconds
3rd5 minutes
4th (final)30 minutes

After all four attempts fail, the job is marked failed and a record is written to the internal dead-letter queue. Contact support with your job_id to recover the payload.

Config Schema

Pass a JSON-encoded config object in the config form field or X-Clean-Config header.

json schema
{
  "columns": {
    "ColumnName":    ["rule1", "rule2"],
    "Phone":         ["PHONE_INTL:NG"],
    "Full Name":     ["NAME"],
    "Email":         ["EMAIL"],
    "DOB":           ["DATE"],
    "Amount":        ["strip", "CURRENCY"],
    "TxnID":         ["KE_MPESA_ID"],
    "NationalID":    ["MASK:4"],
    "CreditCard":    ["ENCRYPT"],
    "Score":         ["to_float", "clamp:0:100"]
  },
  "output_format": "json"
}

Columns not listed in columns are included in the output with whitespace stripped. A column listed with an empty array [] passes through unchanged.

Column Rules

Rules are applied left-to-right. Multiple rules can be chained on one column. Rules that return objects (marked below) produce a nested JSON object in the output — the original column value is replaced.

Phone

RuleReturnsDescription
PHONEstring | null contact Normalise to Kenyan E.164 (254712345678). Returns null if the number is invalid or cannot be formatted.
PHONE_INTLstring | null contact Normalise to international E.164 using auto-detected region. Falls back to PHONE (KE) if detection fails.
PHONE_INTL:CCstring | null contact Same as PHONE_INTL but forces a specific country code. Replace CC with an ISO 3166-1 alpha-2 code: PHONE_INTL:NG, PHONE_INTL:US, PHONE_INTL:GB, PHONE_INTL:ZA, etc.

Email

RuleReturnsDescription
EMAILobject contact Validate and normalise. Returns {"email":"…","valid":true,"reason":null}. Checks RFC 5322 structure, local part ≤ 64 chars, address ≤ 254 chars, no consecutive dots, domain has TLD. Normalises to lowercase.
EMAIL_NORMALIZEstring | null contact Lowercase and trim only. No validation. Returns the cleaned string or null if empty.

Text

RuleReturnsDescription
NAMEstring | nulltext Strip whitespace, title-case, and remove stray punctuation.
stripstringtext Remove leading and trailing whitespace.
lowercasestringtext Convert to lowercase.
uppercasestringtext Convert to uppercase.
title_casestringtext Title-case each word.

Dates & Numbers

RuleReturnsDescription
DATEstring | nullnumeric Parse 10+ common date formats and Excel serial numbers → ISO 8601 (YYYY-MM-DD).
to_intint | nullnumeric Cast to integer. Returns null if not numeric.
to_floatfloat | nullnumeric Cast to float. Returns null if not numeric.
CURRENCYobject | null numeric Extract currency symbol and amount. Returns {"amount":1234.56,"currency":"USD"}. Recognises $, €, £, KSh, ₦, ₹, ISO codes (USD, KES, NGN, …) and more.
clamp:lo:hifloat | nullnumeric Clamp value to [lo, hi]. Either bound can be omitted: clamp::100, clamp:0:.
regex:pattern:replacestringtext Apply re.sub(pattern, replace, value). Use Python regex syntax.

Missing Values

RuleReturnsDescription
drop_empty—missing Drop the entire row if this column is null or blank.
fill_meanfloatmissing Fill null/blank cells with the column mean (numeric columns).
fill_medianfloatmissing Fill null/blank cells with the column median (numeric columns).
fill_value:Xstringmissing Fill null/blank cells with the literal string X. Example: fill_value:N/A, fill_value:0.

Kenya (KE) Locale

RuleReturnsDescription
KE_MPESA_IDobject locale Validate and normalise an M-Pesa transaction ID (10-char alphanumeric, e.g. RK12345678). Returns {"mpesa_id":"RK12345678","valid":true,"reason":null}.
KE_COUNTYstring | null locale Normalise any of Kenya's 47 county names (including common aliases and misspellings) to the official title-case form. Returns null if unrecognised. Examples: "nairobi city" → "Nairobi", "muranga" → "Murang'a".

USA (US) Locale

RuleReturnsDescription
US_ZIPobject locale Validate and normalise a US ZIP code (5-digit or ZIP+4). Returns {"zip":"90210","valid":true,"zip4":null}. Accepts 9-digit runs and auto-inserts the hyphen.
US_SSNobject locale Validate and mask a US Social Security Number. Returns {"ssn_masked":"***-**-6789","valid":true}. The full SSN is never returned. Applies IIRC invalid-range checks (000/666/900+ area codes).

PII & Security

RuleReturnsDescription
MASKstring | null pii Replace every character with *. E.g. "john@example.com" → "****************".
MASK:Nstring | null pii Keep the last N characters visible. E.g. MASK:4 → "************5678".
MASK:N:Cstring | null pii Keep last N chars, use C as the mask character. E.g. MASK:4:X → "XXXXXXXXXXXX5678".
ENCRYPT Pro onlystring | null pii One-way SHA-256 hash of the value. Returns a 64-character hex digest. Zero-knowledge — irreversible by design. Optionally salted via the X-Crypto-Salt header.
ENCRYPT:salt Pro onlystring | null pii Same as ENCRYPT but with a custom per-rule salt embedded directly in the rule string. Takes precedence over X-Crypto-Salt.

Deduplication

RuleScopeDescription
dedupePer-column dedupe Remove rows that are exact duplicates on this specific column. Apply to multiple columns to deduplicate on a composite key.

Dry-Run Mode

Set dry_run=true (form field) or X-Dry-Run: true (header) to validate your config against the uploaded file's column headers without processing any rows.

  • Returns 200 OK immediately — no rows are cleaned.
  • No credits consumed, no billing ledger entry written.
  • valid: true means every column referenced in your config was found in the file.
  • missing_columns lists config columns absent from the file.
  • unmapped_columns lists file columns not in your config (they will pass through).
  • rules_preview shows the exact rules that will run on each matched column.
✦

Use dry-run as part of your pipeline setup to verify column name mapping before sending real data. It is available on all tiers including test keys.

Deduplication

Two deduplication modes are available and can be combined.

Global (whole-row) deduplication

Set dedupe_all=true as a form field or X-Dedupe-All: true as a header. Removes rows where every column value is identical. Applied after all column-level rules have run.

⚑

Starter tier: dedupe_all is limited to files with ≤ 10,000 rows. Pro tier: no row-count restriction. Starter Pro

Per-column deduplication

Apply the dedupe rule to one or more specific columns in your config. Rows are removed when the value in that column (or combination of columns) has already appeared.

json — dedupe on a composite key
{
  "columns": {
    "Email":  ["EMAIL_NORMALIZE", "dedupe"],
    "Phone":  ["PHONE", "dedupe"]
  }
}

The above removes any row whose Email + Phone combination has already appeared. Both columns contribute to the deduplication key.

PII & Encryption

The MASK and ENCRYPT rules are designed so your data never leaves the cleaning pipeline in its original form.

MASK

Replaces characters with a mask character. Operates entirely in volatile RAM — the original value is not stored or logged anywhere.

examples
// Input: "07712345678"
"MASK"    → "***********"     // fully masked
"MASK:4"  → "*******5678"     // last 4 visible
"MASK:4:X"→ "XXXXXXX5678"     // last 4 visible, custom char

ENCRYPT Pro only

Produces a one-way SHA-256 hex digest. The hash is computed in memory and the original value is discarded. Supply a salt via the X-Crypto-Salt header to prevent rainbow-table attacks.

⚿

The salt is never logged, never stored, and never included in any response. Your data remains zero-knowledge — Dodman cannot reverse the hash. Store your salt securely on your end.

python — ENCRYPT with salt
resp = requests.post(
    ENDPOINT,
    headers={
        "Authorization":  f"Bearer {API_KEY}",
        "X-Crypto-Salt":  "my-secret-salt-32chars-minimum",
    },
    files={"file": ("data.csv", f, "text/csv")},
    data={"config": json.dumps({
        "columns": {
            "NationalID": ["ENCRYPT"],
            "CreditCard": ["ENCRYPT"],
        }
    })},
)

import requests, json

API_KEY  = "dk_test_your_key_here"
ENDPOINT = "https://your-deployment-url.com/api/v1/clean"

config = {
    "columns": {
        "Phone":    ["PHONE_INTL:KE"],
        "Name":     ["NAME"],
        "Email":    ["EMAIL"],

    resp = requests.post(
        ENDPOINT,
        headers={"Authorization": f"Bearer {API_KEY}"},

Node.js Example

javascript · fetch + form-data
import fs       from 'fs';
import FormData from 'form-data';
import fetch    from 'node-fetch';

const API_KEY  = 'dk_test_your_key_here';
const ENDPOINT = 'https://your-deployment-url.com/api/v1/clean';

const config = {
  columns: {
    Phone:    ['PHONE_INTL:KE'],
    Name:     ['NAME'],
    Email:    ['EMAIL'],
    JoinDate: ['DATE'],
    Amount:   ['strip', 'CURRENCY'],
  },
  output_format: 'json',
};

const form = new FormData();
form.append('file', fs.createReadStream('members.csv'), 'members.csv');
form.append('config', JSON.stringify(config));

const res = await fetch(ENDPOINT, {
  method:  'POST',
  headers: { Authorization: `Bearer ${API_KEY}`, ...form.getHeaders() },
  body:    form,
});

if (!res.ok) {
  const err = await res.json();
  throw new Error(err.error.message);
}

const rows = await res.json();
console.log(`Cleaned ${rows.length} rows`);
console.log(`Quota remaining: ${res.headers.get('x-quota-rows-remaining')}`);

Webhook + Job Polling

Add the X-Webhook-URL header to receive the cleaned payload asynchronously. The endpoint returns 202 Accepted with a job_id you can poll until delivery is confirmed.

python · webhook + polling
import time, requests, json

API_KEY  = "dk_live_your_key_here"
ENDPOINT = "https://your-deployment-url.com/api/v1"
HEADERS  = {"Authorization": f"Bearer {API_KEY}"}

# 1. Submit the file for async delivery
with open("large_export.csv", "rb") as f:
    resp = requests.post(
        f"{ENDPOINT}/clean",
        headers={
            **HEADERS,
            "X-Webhook-URL": "https://your-server.com/hooks/cleaned",
        },
        files={"file": ("large_export.csv", f, "text/csv")},
        data={"config": json.dumps({"columns": {"Phone": ["PHONE"], "Name": ["NAME"]}})},
    )
resp.raise_for_status()
job = resp.json()
job_id = job["job_id"]
print(f"Queued: {job_id}")

# 2. Poll until terminal state
while True:
    status = requests.get(f"{ENDPOINT}/jobs/{job_id}", headers=HEADERS).json()
    print(f"Status: {status['status']}")
    if status["status"] in ("delivered", "failed"):
        break
    time.sleep(4)

if status["status"] == "failed":
    print(f"Delivery failed: {status['error']}")
✓

Your webhook endpoint must respond with a 2xx status within 30 seconds. Failed deliveries are retried up to 3 additional times (30 s, 5 min, 30 min). 4xx responses short-circuit the retry loop immediately.
